# Geometric Prototype-Rule Explanation of a Black-Box Regressor

Explaining a black-box regressor as a barycentric blend of geometric "prototype"
corners — a Delaunay/simplex-based Takagi–Sugeno fuzzy-rule construction — and
studying when that explanation is trustworthy.

## One-line summary

Every prediction is reframed as "this point is X% prototype A + Y% prototype B + …",
where the weights are barycentric coordinates (they sum to 1) over a simplex of
prototype corners. Each corner has a human-readable label, so the mixture of
activated rules becomes the explanation.

## The finding

**Coverage and fidelity are decoupled — and the reason is mechanical, not
coincidental.** Coverage (can a point be explained at all?) and fidelity (is
the explanation faithful to the model?) look like they should move together —
more corners, better explanations, right? They don't, because they are
questions asked in two different spaces.

**Why they decouple.** The method only knows how to draw triangles in 2D, so
before anything else happens, the original features are flattened from their
native dimension down to 2D with PCA (`embed_2d`). That projection is lossy —
whatever variance PCA doesn't keep is gone, permanently, before a single
corner is picked.

- **Coverage** is computed entirely inside that flattened space
  (`tri.find_simplex(xy[i]) >= 0` — note it only ever touches `xy`, the 2D
  projection). Adding corners subdivides the same flat cloud into finer
  triangles, so more of the cloud falls inside *some* simplex. Coverage climbs
  because it is purely a question about point density in 2D — it never asks
  whether the 2D position is still an honest summary of the original point.
- **Fidelity** is checked against the real target value, which was produced
  from the original, un-flattened features. If PCA's 2D projection kept most
  of the relevant variance, the blend is still close to the truth. If it
  didn't, the blend is confidently interpolating between prototypes using a
  coordinate that already threw away the information fidelity needs — and
  more corners cannot put that information back. They only re-slice the same
  incomplete sheet more finely.

So: coverage lives entirely inside the projection and improves as you refine
it; fidelity is a referendum on how much the projection lost *before*
refinement even starts. That's the mechanism, and it's why high coverage can
give a false sense of security — a point being "explainable" says nothing
about whether the explanation is faithful.

Two further properties fall out of the same geometry:

- **Sparsity is a free confidence signal.** The dominant barycentric weight
  tracks the model's certainty: extreme inputs collapse onto a single
  prototype (~100%), ambiguous inputs produce a near-even multi-prototype
  blend. (NEEDS MORE TESTING)
- **Honest abstention.** A point outside the convex hull of prototypes gets
  *no* explanation rather than a fabricated one — a genuine contrast with
  attribution methods (LIME/SHAP) that always return something, even for
  inputs unlike anything seen.

## Real-data validation

Decoupling is demonstrated two ways:

**1. Controlled sweep** — `experiments/robustness_experiment.py`. One
synthetic dataset, noise dialed up to slide predictor redundancy down.
Coverage stays flat while fidelity error grows sharply. This isolates the
mechanism: as noise increases, the data stops being a thin, near-2D sheet, so
the same PCA projection keeps less of what fidelity needs while coverage —
still just a density question in 2D — barely notices.

**2. Across real datasets** — `experiments/decoupling_multidataset.py`. Three
genuinely different real datasets spanning a redundancy range, with a
RandomForest black box. Full results in `results/decoupling_results.md`
(regenerated by the script); mean of 5 seeds at 10 corners:

| dataset  | predictor mutual R² | 2D variance kept | black-box R² | coverage@10 | fidelity@10 |
|----------|--------------------:|-----------------:|-------------:|------------:|------------:|
| bodyfat  |               0.754 |             94.6% |        0.555 | 90.9% ±3.4% | 0.1541 ±0.0030 |
| energy   |               1.000 |             96.5% |        0.853 | 81.0% ±5.0% | 0.2958 ±0.0552 |
| concrete |              −0.479 |             77.5% |        0.103 | 90.5% ±4.9% | 0.4635 ±0.0957 |

Coverage error bars overlap across all three (a flat, geometry-driven axis)
while fidelity error bars are cleanly separated (~3× worse on concrete than
bodyfat). Note the "2D variance kept" column: concrete's PCA projection keeps
the least variance of the three (77.5%), and concrete also has the worst
fidelity — consistent with the mechanism above, though the relationship isn't
a clean monotonic law (see caveat below). The two axes move independently —
decoupling, on real data.

**Important caveat:** this is *not* a clean monotonic law fidelity = f(mutual
R²) or fidelity = f(2D variance kept). Energy's simulated building geometry
makes its predictors near-perfectly mutually predictable (R² ≈ 1.0) and keeps
96.5% of variance in 2D, yet its fidelity is worse than bodyfat's. The claim
is that coverage and fidelity are *independent axes*, not that fidelity is a
simple function of predictor redundancy or projection quality alone.
(Fidelity also tracks how well the black box itself can fit the target — note
concrete's black-box R² of 0.10 alongside its high fidelity error: some of
that error is the black box being genuinely hard to fit, not just the
projection losing information.)

## Applications

`applications/bodyfat/` applies the explainer to the real StatLib body-fat
dataset (Penrose 1985, 252 men). Each body-fat estimate is explained as a
blend of body-type prototypes with human-readable labels ("high abdomen, high
hip, high chest"). On real data:

- black-box R² ≈ 0.70 (abdomen, hip, chest → body fat %);
- single-prototype explanations (~100%) for extreme builds, three-way blends
  for ambiguous ones — the sparsity-as-confidence signature;
- honest abstention for people outside the prototype hull;
- **label collisions** — several prototypes share the label "high abdomen,
  high hip, high chest" but carry different body-fat values (e.g. 24% vs 48%).
  This is not a bug: it faithfully reports that circumference does not fully
  determine body fat (black-box R² < 1).

The interactive walkthrough is `notebooks/bodyfat_scratch.ipynb`. The
mechanism above — build the intuition first — is worked out step by step in
`notebooks/scratch.ipynb`, including the exact moment the 4D→2D projection
happens and why that step is where fidelity's ceiling gets set.

## What is / isn't novel

- **Established:** Delaunay-triangulation-based Takagi–Sugeno fuzzy models
  using barycentric coordinates as rule firing strengths; prototype-based
  explanation.
- **Novel:** the coverage/fidelity decoupling — including the mechanical
  explanation for *why* it happens (coverage is a property of the lossy 2D
  projection; fidelity is a property of what that projection discarded) —
  shown on both a controlled setup and multiple real datasets, plus the
  observation that coverage alone can mislead.

## Setup

    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt

## Running things

    # core library self-test
    python src/quad_fuzzy.py

    # tests
    python tests/test_quad_fuzzy.py
    python tests/test_bodyfat.py

    # decoupling experiments
    python experiments/robustness_experiment.py
    python experiments/decoupling_multidataset.py            # single seed
    python experiments/decoupling_multidataset.py --seeds 5  # with error bars
                                                             # -> writes results/

    # body-fat application
    python applications/bodyfat/bodyfat_explainer.py

The multi-dataset experiment fetches the concrete and energy datasets from the
UCI repository via `ucimlrepo`; the body-fat CSV is included under
`applications/bodyfat/data/`.
